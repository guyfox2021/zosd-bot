# Codex: ZOSD Telegram Bot

Дата: 2026-05-07

## Обзор проекта

Это Telegram-бот на `aiogram` с архитектурой:
- `main.py` — точка входа
- `app/config.py` — загрузка конфигурации из `.env`
- `app/db.py` — SQLite через `aiosqlite`
- `app/routers.py` — маршрутизация роутеров обработчиков
- `app/handlers/` — логика пользовательских и админских команд
- `app/keyboards/` — клавиатуры Reply и Inline
- `app/middlewares/subscription.py` — проверка подписки на канал
- `app/states.py` — FSM состояния
- `app/utils.py` — вспомогательные утилиты и проверки прав администратора

## Конфигурация

`app/config.py` ожидает:
- `BOT_TOKEN` — токен бота
- `ADMIN_IDS` — список админов через запятую
- `DB_PATH` — путь к SQLite базе (по умолчанию `bot.db`)

## Цель и концепция

Документ описывает проект как связку Telegram-канала и бота:
- бот принимает анонимные вопросы и предложения от курсантов
- канал публикует ответы и полезную информацию для всех
- курсант может написать без раскрытия личности
- ответ может быть отправлен лично либо опубликован в канале
- формат публикации должен быть:
  - вопрос курсанта анонимно
  - официальная ответная часть
  - без имён, без подразделений, без персональных данных

Ценность:
- для курсантов: анонимность, простота, единое место ответов, шпаргалка
- для руководства: понятный канал коммуникации, меньше слухов и недопониманий

Важно:
- анонимность сохраняется, если курсант не пишет о себе в тексте
- администратор в текущей реализации не видит отправителя только косвенно через логику бота, но реальное анонимное хранение зависит от бизнес-правил

## Основной запуск

`main.py` делает следующее:
- подключает логирование
- загружает конфиг
- подключается к базе и создаёт таблицы
- создаёт экземпляр `Bot` и `Dispatcher`
- подключает middleware `SubscriptionMiddleware`
- подключает роутер из `app/routers.py`
- запускает polling
- корректно закрывает базу при остановке

## База данных

Таблицы и данные:
- `users(user_id, first_seen_at)`
- `tickets(id, user_id, text, created_at, status, answer_text, answered_at)`
- `cheat_sections(id, title, sort_order)`
- `cheat_items(id, section_id, title, content, sort_order)`

Дополнительно:
- seed начального раздела и пункта, если таблица `cheat_sections` пуста
- методы CRUD для разделов и пунктов шпаргалки
- логика перемещения пунктов по порядку

## Пользовательский функционал

Пользователь может:
- `/start` — регистрация и главное меню
- отправить анонимное обращение (`❓Анонімні питання/пропозиції/скарги`)
- открыть шпаргалку (`📚 Шпаргалка`)
- получить ID и проверить права администратора через `id`/`ID`/

Пользовательские запросы:
- создаются как тикеты в базе
- отправляются администраторам со inline-кнопкой `✉️ Відповісти`

## Админский функционал

Администратор может:
- открыть `Панель адміністратора`
- просмотреть статистику користувачів, звернень та шпаргалки
- запустить рассылку всем зарегистрированным пользователям
- редактировать шпаргалку:
  - добавлять, переименовывать и удалять разделы
  - добавлять, редактировать, удалять и перемещать пункты
- отвечать на тикеты

Функции админа защищены проверкой `is_admin(user_id, config)`.

## Middleware подписки

`app/middlewares/subscription.py` проверяет, подписан ли пользователь на канал:
- `CHANNEL_USERNAME = "@your_channel"`
- есть кнопка перехода в канал и проверка подписки
- результаты кешируются на 60 секунд
- блокирует сообщения и callback'и, если пользователь не подписан

## Итого

Текущий бот реализован как Telegram-сервис с анонимными обращениями, админ-панелью и управляемой шпаргалкой. Структура логична и соответствует `aiogram`-паттернам, но в репозитории есть оставшиеся ссылки на отсутствующие debug-модули.

## Комментарий по документу

Документ описывает проект как систему "канал + бот". В текущем коде:
- бот принимает анонимные вопросы и сохраняет их в базе
- админ отвечает через личное сообщение пользователю
- публикация ответа в канал не реализована явно

Это важно: концепция канала описана, но техническая реализация пока ограничена личными отправками и админской панелью.
